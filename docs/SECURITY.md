# Безопасность

## Что даёт бот и чем это опасно

Токен бота и ваш чат дают управление роутером: блокировка устройств, перезагрузка, Wake-on-LAN, просмотр списка устройств
и DNS-статистики. Относитесь к токену как к паролю.

## Меры, заложенные в бота

- **Только свой чат.** Сообщения и нажатия кнопок от любого `chat_id`, кроме указанного в `/etc/tgbot.conf`, игнорируются.
- **Токен не в репозитории.** Он лежит только на роутере: `/etc/tgbot.conf`, `chmod 600`. Установщик передаёт его через stdin, а не в аргументах команды.
- **Исходящие соединения только.** Бот сам ходит в Telegram; на роутере не открывается ни одного порта.
- **Подтверждение для перезагрузки** (кнопка «Да»).
- **Защита от повторов** после перезагрузки: старые сообщения отбрасываются при старте слушателя.
- **Нельзя заблокировать сам роутер.**
- **Минимум данных наружу**: производитель определяется по префиксу MAC (3 байта); `/speedtest` обращается к Cloudflare.

## Что нужно знать о новых функциях

- **`/vpn add`** присылает **приватный ключ** (QR и `.conf`) через Telegram. Сообщения удаляются через 2 минуты, но Telegram не даёт сквозного шифрования для ботов,
  поэтому ключ на время проходит через серверы Telegram. Создание требует подтверждения кнопкой. Если это неприемлемо, создавайте VPN-пользователей в админке роутера.
  Утёкший пир отзывается командой `/vpn del Имя`.
- **Бэкап** содержит пароли Wi-Fi и ключи WireGuard, поэтому всегда шифруется (`BACKUP_PASS`); без пароля он не отправляется.
- **`/scan` и проверка портов** работают только с устройствами вашей локальной сети.
- **Блокировка и перезагрузка** доступны только вашему `chat_id`.

## Home Assistant

- **Токен HA** (`/etc/tgbot.ha`, `chmod 600`) даёт права пользователя HA, который его создал. Бот только читает, поэтому лучше выпустить токен от отдельного пользователя без прав администратора. Отзыв — в профиле HA.
- **Webhook-и HA** принимаются только из локальной сети (`local_only: true`), их id хранятся в `/etc/tgbot.hooks/*` (`chmod 700`), в репозиторий не попадают.
- **Токен бота есть и в HA** (`secrets.yaml`, `tg_send_url`): при смене токена обновите оба места.
- **Raspberry Pi** с HA: вход по SSH только по ключу, надёжный пароль пользователя; секретные ссылки календарей хранятся в HA.
- Репозиторий публичный: не коммитьте реальные `automations.yaml` с webhook-id, `secrets.yaml`, ссылки календарей.

## Что сделать вам

1. **Никогда не публикуйте токен**, в том числе в чатах, issue и скриншотах. Если токен утёк: **@BotFather → `/revoke`**, затем обновите `/etc/tgbot.conf` и выполните `tgbot-ctl on`.
2. **Не коммитьте** `tgbot.conf`. Файл добавлен в `.gitignore`.
3. Закройте SSH по паролю (только ключи), см. [ROUTER-SETUP.md](ROUTER-SETUP.md).
4. Защитите аккаунт Telegram двухфакторной аутентификацией: доступ к вашему чату = доступ к боту.
5. Убедитесь, что роутер не виден из интернета (политика `wan` = `DROP`), см. [ROUTER-SETUP.md](ROUTER-SETUP.md).

## Чего бот не делает

- Не хранит и не отправляет содержимое вашего трафика: только домены из журнала AdGuard (локально, для отчётов) и служебные данные о состоянии роутера.
- Не открывает доступ из интернета и не меняет настройки файрвола.

## Сообщить об уязвимости

Если нашли проблему безопасности, не публикуйте её в открытом issue: напишите владельцу репозитория напрямую.
