# Как это устроено

## Состав

```
router/
├── usr/bin/tgbot.sh        периодические проверки (cron, раз в минуту)
├── usr/bin/tgbot-poll.sh   слушатель команд и кнопок (демон, long polling)
├── usr/bin/tgbot-wol.lua   отправка Wake-on-LAN (Lua + luasocket)
├── usr/bin/tgbot-png.lua   QR-код в PNG (штатный qrencode собран без PNG)
├── usr/bin/tgbot-scan.lua  проверка портов и TCP-доступности
├── usr/bin/tgbot-ctl       управление: on / off / status / remove
├── usr/lib/tgbot-lib.sh    общая библиотека: отправка, имена, блокировка, отчёты, команды
├── usr/lib/tgbot-ext.sh    слежение, сайты, VPN из бота, бэкап, история скорости, дайджест
├── etc/init.d/tgbot        служба procd для слушателя
└── etc/tgbot.conf.example  пример конфига (TOKEN, CHAT_ID)
```

Данные на роутере:

| Файл | Где | Назначение |
|---|---|---|
| `/etc/tgbot.conf` | флеш, `chmod 600` | токен и chat_id |
| `/etc/tgbot.known` | флеш | MAC известных устройств |
| `/etc/tgbot.names` | флеш | свои имена `mac=Имя` |
| `/etc/tgbot.watch` | флеш | отслеживаемые устройства `mac=home\|alive` |
| `/etc/tgbot.sites` | флеш | мониторинг сайтов, по цели в строке |
| `/etc/tgbot.speed` | флеш | история скорости `epoch,вниз,вверх,пинг` (до 400 записей) |
| `/etc/tgbot.traffic` | флеш | суточные снимки счётчиков WAN `epoch,rx,tx` |
| `/etc/tgbot.events` | флеш | журнал событий `epoch\|тип\|текст` (для дайджеста, до 600 строк) |
| `/tmp/tgbot.*` | RAM | состояния (offset, VPN, флаги тревог), сбрасываются при перезагрузке |

Флеш-память не изнашивается: частые записи идут только в `/tmp`.

## Два процесса

1. **Слушатель (`tgbot-poll.sh`)**. Постоянно держит запрос `getUpdates` с `timeout=50`
   (long polling). Пока сообщений нет, процесс спит и не потребляет CPU. Пришла команда или
   нажатие кнопки: отвечает сразу. Запускается через procd с автоперезапуском.
2. **Периодические проверки (`tgbot.sh`)**. Cron раз в минуту. Запуск занимает доли секунды.
   Защита от наложения: каталог-замок `/tmp/tgbot.lock`.

Замеры на Flint 2 (4 ядра, 1 ГБ): бот занимает около 0% CPU, ~1,2 МБ памяти, весь код ~70 КБ.

## Как работают проверки

- **Новые устройства**: список активных клиентов `br-lan` из `/proc/net/arp` (флаг `0x2`) сравнивается с `/etc/tgbot.known`. Первый запуск только запоминает.
  Подключение определяется по `iwinfo <iface> assoclist` (`ra0` = 2,4 ГГц, `rax0` = 5 ГГц, `ra1/rax1` = гостевые).
- **VPN**: для каждого пира из UCI `wireguard_server` берётся `wg show wgserver latest-handshakes`; онлайн = handshake моложе 240 с. Состояние хранится в `/tmp`, смена состояния = уведомление.
- **Интернет**: `ping` до `1.1.1.1` и `8.8.8.8`. Метка начала пропажи в `/tmp/tgbot.wandown`; сообщение отправляется после восстановления (пока связи нет, отправить нечем).
- **Аномалии DNS**: раз в 10 минут разбирается `querylog.json` AdGuard Home за последние 10 минут (`jq`), считаются запросы и блокировки на клиента.
- **Железо**: температура `thermal_zone0`, `MemAvailable`, `df /overlay`.

## Блокировка устройств

Используется штатный механизм GL.iNet: MAC добавляется в UCI `gl_block.block_mac.mac` и в ipset `GL_MAC_BLOCK`;
правило `iptables -I FORWARD -m set --match-set GL_MAC_BLOCK src -j DROP` создаёт `/usr/bin/gl_block.sh`.
Поэтому блокировка видна и в админке GL.iNet, и переживает перезагрузку. Дополнительно сбрасываются соединения
устройства в conntrack. Устройство остаётся подключённым к Wi-Fi, но без интернета и без доступа в другие сети.
Сам роутер заблокировать нельзя (проверка MAC `br-lan`).

Этот механизм специфичен для **GL.iNet**. На чистом OpenWrt замените `do_block` / `do_unblock`
в `tgbot-lib.sh` на правило файрвола (`uci firewall` с `src_mac`).

## Новые возможности

- **Присутствие и слежение**: каждую минуту для каждого устройства из `/etc/tgbot.watch` проверяется Wi-Fi-ассоциация (`iwinfo assoclist`), затем ping по IP из ARP.
  «Ушёл» фиксируется после N минут без сигнала (дебаунс: телефоны на время засыпают).
- **Проверка портов**: `tgbot-scan.lua` пробует подключиться к ~20 типичным портам (таймаут 0,4 с). Запускается для каждого нового устройства и по `/scan`.
- **Сайты**: HTTP(S) через `curl` (коды 2xx и 3xx = «работает») или TCP через `tgbot-scan.lua --tcp`. Тревога после 2 неудач подряд.
- **История скорости**: ночной замер через Cloudflare (`speedtest_raw`), текстовый график из символов `▁▂▃▄▅▆▇█`.
- **Трафик WAN**: суточные снимки `rx_bytes/tx_bytes` интерфейса WAN, при подсчёте учитывается сброс счётчиков при перезагрузке.
  Трафик по отдельным устройствам не считается (нужен отдельный учёт на файрволе).
- **VPN из бота**: создаёт пира в UCI `wireguard_server`, применяет `wg set` без перезапуска, строит конфиг, `qrencode -t ASCII` → `tgbot-png.lua` → `sendPhoto`.
  Сообщения с ключом удаляются через 2 минуты (`deleteMessage`); таймер живёт в фоновом процессе слушателя.
- **Бэкап**: `sysupgrade -b` → `openssl enc -aes-256-cbc -pbkdf2` → `sendDocument`. См. [BACKUP.md](BACKUP.md).
- **Недельный дайджест**: агрегирует журнал AdGuard, `/etc/tgbot.events`, историю скорости и трафика.

## Безопасность при перезагрузке

При старте слушатель вызывает `getUpdates?offset=-1`, отбрасывая накопленные сообщения и нажатия кнопок.
Иначе после перезагрузки мог бы повторно сработать старый `reboot:yes`.

## Зависимости

`curl`, `jq`, `lua` (с luasocket и `bit`), `ipset`, `conntrack`, `iwinfo`, `wg`, `openssl`, `sysupgrade`, BusyBox `ash`, cron; для `/vpn add` ещё `qrencode` (`opkg install qrencode`). Всё это есть в прошивке GL.iNet 4.x.
Внешние сервисы: `api.telegram.org`, `api.macvendors.com` (только префикс MAC), `speed.cloudflare.com` (только `/speedtest`).

## Известные ограничения

- Все функции делят глобальные переменные `sh`: при доработке не используйте имена вроде `mac`, `sf`, `name` в вызывающем коде после вызова функций (локальных переменных в `ash` нет).
- Бот не знает о полном отключении роутера; для этого нужен внешний мониторинг (например, healthchecks.io).
- Команды, отправленные пока роутер выключен, теряются (намеренно, см. выше).
- Wake-on-LAN отправляет пакет, но включится ли ПК, зависит от настроек BIOS и сетевой карты.
- Кнопки и `/reboot` проверены на уровне логики; рекомендуется проверить на своём устройстве.
- Точное имя и состав интерфейсов Wi-Fi (`ra0`, `rax0`, ...) в `connection()` рассчитаны на Flint 2 (MediaTek).
